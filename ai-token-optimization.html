Token Usage Optimization

Ask InSight answers natural-language questions about traffic metrics and renders maps, tables, and charts. Its instruction stack had grown to ~93,000 characters across system prompts, MCP tool definitions, and reference guides. Because multi-step agent loops re-send that context on every tool call, a single question cost 84k–99k tokens. I led an end-to-end context-engineering initiative that gave every rule a single authoritative owner, moved reference docs to on-demand loading, and verified every change with dedicated eval suites.

The challenge

In an agentic loop, context cost can add up quickly. Each sequential tool call re-sends the entire static prefix, so 3 tool calls ≈ 80k–100k+ tokens for one question. The ~93,000-character instruction stack had also accumulated duplication and contradictions: the same query rules were paid for in the system prompt, in MCP tool docstrings, and again in markdown reference resources, and conflicting instructions (“always call the metrics catalog” vs. “call only when uncertain”) degraded accuracy.

Baseline: ~23,200 tokens of static instructions and 83.7k–99.4k tokens per user prompt, with an ~87% pass rate on the 30-case analytics benchmark.

What I did

I audited every instruction layer (system prompt, MCP tool descriptions, static resources, domain skills) plus multi-step evaluation traces, and read the agent framework and MCP adapter source to verify how context actually behaves — not assumptions. The guiding principles: every operational rule gets a single authoritative owner; in a multi-step agent, removing one round trip saves more tokens than deleting thousands of characters of prose; and every context cut is paired with evals so regressions surface immediately.

  • Single-owner instruction model: the host prompt now owns persona, safety gates, and UI rendering; tool schemas own parameters and error recovery; live catalog tools own dynamic definitions; on-demand resources own deep examples. The static corpus dropped from 92,893 to 70,603 characters (−24%), including a −53% cut to the main capabilities guide.
  • Progressive disclosure instead of mandatory pre-loads: removed the mandatory pre-query resource load (the framework discarded it one step later anyway) and instructed the agent to load reference docs only immediately before the tool call they inform, plus parallel tool execution for multi-part questions. Average tool calls per turn fell from 3.5–3.8 to 2.6.
  • Conflict fixes, verified by a new regression suite: resolved the contradictory instructions and authored a 10-case Instruction Stack Regression Suite (tool-call assertions, UI envelope checks, judge rubrics), run in gated stages against the existing 30-case Canonical Suite before and after each change.

Value added

Mean tokens per user question fell −20–31%, the canonical benchmark pass rate rose from ~87% to 97–98%, and privacy & safety refusal evals passed 100% (15/15). Follow-on work stripped ~5,800 tokens/call of dead output-schema overhead on newer models, and a four-line structured-geography rule cut token usage on lite models by 19% and query failures by 38%.
