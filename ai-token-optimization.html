Token Usage Optimization

An agentic AI assistant answers natural-language questions about data and visualizes the results. Its instruction stack had grown large and redundant across prompts, tool descriptions, and reference guides, and because a multi-step agent re-sends its context at every step, a single question was costing a lot in tokens. I led an end-to-end context-engineering initiative that gave every rule a single authoritative home, moved reference material to on-demand loading, and verified every change with dedicated eval suites.

The challenge

In an agentic loop, context cost compounds quickly: each sequential step re-sends the accumulated context, so token usage grew fast with every additional step. The instruction stack had also accumulated duplication and contradictions — the same rules were repeated across the prompt, tool descriptions, and reference documents, and conflicting guidance degraded answer quality.

Baseline: a bloated static instruction corpus and an ~87% pass rate on a 30-case internal analytics benchmark.

What I did

I audited every instruction layer plus multi-step evaluation traces, and read the underlying agent framework’s source to verify how context actually behaves — not assumptions. The guiding principles: every rule gets a single authoritative home; in a multi-step agent, removing one round trip saves more tokens than deleting thousands of characters of prose; and every context change is paired with evals so regressions surface immediately.

  • Single-owner instruction model: each rule now lives in exactly one authoritative place instead of being repeated — and sometimes contradicted — across prompts, tool descriptions, and reference docs. The static instruction corpus shrank by about a quarter, with the deepest cuts to the main usage guide.
  • On-demand loading instead of mandatory pre-loads: reference material is fetched only when it is actually needed, and independent steps run in parallel where possible. Average steps per question fell from 3.5–3.8 to about 2.6.
  • Conflict fixes, verified by a new regression suite: resolved the contradictory guidance and added a dedicated regression suite, run alongside the existing 30-case benchmark before and after every change.

Value added

Mean tokens per question fell −20–31%, the benchmark pass rate rose from ~87% to 97–98%, and safety-refusal evals passed 100% (15/15). Follow-on work delivered further double-digit token reductions on smaller models and a significant drop in query failures.
