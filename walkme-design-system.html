Design System for In-App Guidance

With the input of our UX team, I built and rolled out a design system for StreetLight's in-app guidance on WalkMe: a decision framework for when to use which kind of guidance, paired with reusable templates for how to build it. The result is guidance that's consistent across products, faster to ship, and matched to the user's actual need rather than built ad hoc.

The challenge

WalkMe guidance across our products had grown large but inconsistent, with no shared standard for which component to use in a given situation, styles that drifted depending on who built it, and no common vocabulary in requirements and reviews.

What I did

  • Designed a decision framework that maps five user-need types (onboarding, ongoing tasks, reference, new features, operational alerts) to the right guidance format and trigger
  • Built a library of 10 reusable component templates (tutorials, tours, modals, popups, tooltips, banners) with implementation steps and autoplay rules
  • Wrote the content patterns: task-based tutorials of 3–6 steps, brief on-demand tours, and nonblocking popups that explain why, not just where to click
  • Set up governance — templates, folder structure, and a pattern that lets non-developers maintain guidance without code changes — so the system stays consistent as it grows

Value added

New guidance now ships faster and looks and reads the same across products, because teams build from shared templates instead of starting from scratch. Adoption and consistency metrics are still being measured — the measurement plan covers template usage, rule adherence, and user-facing outcomes like tutorial completion.
